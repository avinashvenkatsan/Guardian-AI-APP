🌍 About the Project
Guardian is a web application focused on natural disaster awareness, emergency preparedness, and access to safety resources.

The project aims to provide a centralized interface where users can explore disaster-related information, review safety guidance, and access available emergency assistance features.

Guardian is designed with an emphasis on usability, clear information presentation, and responsible handling of emergency-related information.
🎯 Objectives
- Improve access to disaster awareness information.
- Encourage emergency preparedness and safety planning.
- Provide a simple interface for accessing emergency assistance features.
- Explore location-aware disaster information and alerting capabilities.
- Build an extensible application that can evolve with additional features.
🚀 Features
Disaster Awareness
- Interface for accessing disaster-related information.
- Support for presenting natural hazard information where available.
- Potential for location-aware disaster information.
Emergency SOS
- Emergency assistance interface.
- Access to available emergency contact options.
- Location-related functionality where implemented and permitted by the user.
Disaster Alerts
- Interface for presenting disaster warnings and related information.
- Support for future integration with trusted disaster information sources.

Safety and Preparedness

User Interface
- Organized navigation and information presentation.
- Responsive design for supported devices.

Feature availability depends on the current implementation. Features should be described as operational only after they have been tested.

🔄 How It Works
The intended application workflow is:
1. The user opens the Guardian application.
2. The user accesses available disaster information and safety resources.
3. The application displays information supported by its current implementation.
4. The user accesses available emergency assistance features when needed.
5. The user follows official safety guidance and contacts the appropriate emergency services during an actual emergency.
The availability and reliability of disaster data, location services, alerts, and SOS communication depend on the implementation and external services.
💻 Getting Started
Prerequisites
Depending on the project configuration, you may need:
- A modern web browser.
- Visual Studio Code or another code editor.
- Git.
- Node.js and npm, if required by the project.
1. Clone the Repository
Open a terminal and run:
git clone https://github.com/avinashvenkatsan/Guardian-AI-APP.git
cd Guardian-AI-APP
2. Install Dependencies
If the repository contains a package.json file, install the dependencies using:
npm install
3. Configure Environment Variables
If the project requires environment variables, configure them according to the project's setup instructions.

Do not commit private credentials, passwords, or API keys to the repository.
4. Run the Application Locally
If the project defines a development script in package.json, run:
npm run dev
Open the local URL shown in the terminal.

Note: The commands above apply to a compatible Node.js project. Check the actual repository files for the correct framework, scripts, and installation instructions.

🧪 Testing
Recommended testing areas include:
- Navigation: Verify that links, buttons, and pages work correctly.
- Disaster information: Check data accuracy, freshness, and source attribution.
- Emergency SOS: Test the workflow without unintentionally contacting emergency services.
- Location permissions: Verify behavior when location access is granted or denied.
- Connectivity: Check which features remain available during network interruptions.
- Responsive design: Test on different screen sizes and supported browsers.
- Error handling: Ensure that users receive clear feedback when something fails.
Emergency-related functionality should be tested carefully before being relied upon.
🔒 Security and Privacy
Guardian may handle sensitive information if features involving location, user profiles, medical details, or emergency contacts are implemented.
- Request only the permissions needed for a feature.
- Explain how personal information is collected and used.
- Keep private credentials out of source control.
- Avoid exposing sensitive data in application logs.
- Validate user inputs and handle failures safely.
- Provide appropriate controls for clearing locally stored information where applicable.
Security protections and legal compliance should be claimed only after they have been implemented and verified.
⚠️ Limitations
- Disaster information may be delayed, incomplete, or unavailable.
- Some features may require internet access or device permissions.
- Opening a phone dialer or SMS composer does not guarantee that a call or message has been delivered.
- A web application cannot guarantee communication during network or infrastructure failures.
- Guardian does not replace official emergency warning systems or emergency services.
